# Optimizer Results — Reference

Source: chapter 6 of `context-engineering-dspy-book` (MIT), `CHAPTER_RESULTS.md`
and `results/expanded_notebooks/*/full/result.json`. Repo pins `dspy==3.3.0`.

## How the numbers were produced

The twelve optimizer notebooks are generated templates. They contain **no
executable optimizer code** — every real call lives in
`chapter06/optimizer_runtime.py`, and the notebooks replay checked-in artifacts
unless `CHAPTER06_RUN_LIVE=1`. So the notebooks are documentation of runs, not
the runs themselves. Read `optimizer_runtime.py` for the real code.

Task: binary AI-text detection.

```python
class DetectAIText(dspy.Signature):
    """Decide whether the supplied passage was generated by an AI."""
    text: str = dspy.InputField(desc="Passage to classify")
    is_ai: bool = dspy.OutputField(desc="True for AI-generated text; otherwise False")
```

Data: 300 rows as 150 semantic human/AI pairs. Split is **pair-grouped**, not
row-grouped, so a passage and its rewrite never straddle the split — 160 train,
60 validation, 80 locked test, SHA-256 verified on load.

Metric: `exact_match`, accuracy only.

Baseline: 53.75% test (43/80), 55.00% validation, $0 compile cost.

## Ensemble composition

```python
labeled      = dspy.LabeledFewShot(k=4).compile(detector.deepcopy(), trainset=trainset)
bootstrapped = dspy.BootstrapFewShot(...).compile(detector.deepcopy(), trainset=trainset)
searched     = dspy.BootstrapFewShotWithRandomSearch(...).compile(detector.deepcopy(), ...)

def boolean_majority(predictions):
    return dspy.majority(predictions, field="is_ai", normalize=lambda v: str(v).lower())

dspy.Ensemble(reduce_fn=boolean_majority).compile([labeled, bootstrapped, searched])
```

`deepcopy()` before each compile is not optional — compiling the same object
three times stacks demos. Evaluation cost 3.7× baseline, latency 4.803s vs
1.789s.

## BetterTogether

```python
dspy.BetterTogether(metric=exact_match, p=prompt_optimizer, w=finetuner).compile(
    detector, trainset=trainset, teacher=teacher, valset=valset,
    strategy="p -> w", optimizer_compile_args={"p": {"teacher": teacher}})
```

The `optimizer_compile_args` override exists because BetterTogether normalizes
its teacher to a list for weight optimizers while BootstrapRS expects one
module. Expect this kind of plumbing when composing optimizers.

## BootstrapFinetune

Student `Qwen/Qwen2.5-0.5B-Instruct` via `LocalProvider`; teacher is the
frontier reflection model. PyTorch + Transformers + TRL + PEFT on Apple MPS or
CUDA. `use_peft=True`, 10 epochs, batch 1, gradient accumulation 4, learning
rate 2e-4, max sequence length 768.

The chapter subclasses the optimizer to reject one-class accepted-trace sets
with the message "Use a stronger teacher." Recorded accepted traces: 77 human,
63 AI. It really ran; the fine-tuned weights are git-ignored and only a
manifest of hashes is committed.

## The dataset-size experiment

The only hand-written notebook in the chapter. It varies dataset size rather
than optimizer choice, asking: *"can a reflective prompt optimizer recover a
useful classifier when the unoptimized task model is near chance?"*

Result: GEPA reached 80.0% on validation and 80.0% on the previously untouched
test. Uplift +26.25 points (relative +48.8%), McNemar p = 0.000104 across 29
discordant pairs, bootstrap 95% CI [16.25, 36.25] points over 40 pairs and
10,000 samples, 684 metric calls, 10 candidates, $0.5824 optimization plus
$0.0396 evaluation.

Its stated limit is part of the result: the holdout was made adversarial using
baseline-only predictions, so it should not be generalized.

Parse failures are kept as incorrect with `status: parse_error` and, in the
chapter's words, "never dropped from a denominator." Copy that discipline.

## Corrections

- The chapter README claims `gepa.ipynb` contains a custom `WordLimitProposer`. No such symbol exists anywhere in chapter 6. Do not repeat that claim.
- `bootstrap-finetune.ipynb` text says "DSPy 3.2.1's `LocalProvider`" while the repo pins 3.3.0; the TRL keyword shim is version-sensitive.
- Model identifiers are book-internal aliases, not public model names.
- `dspy.Ensemble` is the legacy teleprompter: `compile` takes a program list, no trainset, no metric.
